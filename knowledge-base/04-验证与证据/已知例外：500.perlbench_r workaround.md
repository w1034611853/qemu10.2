# 已知例外：500.perlbench_r workaround

## 问题是什么

`500.perlbench_r test` 的失败模式里，有一类并不是 NZCV 优化把 guest 结果算错了，而是 nested Perl subprocess 绕开了外层 `qemu-aarch64` launcher。

## 典型症状

- `makerand.out` 正常
- `test.out` 大量 miscompare
- `test.err` 里出现 guest ELF 被宿主 shell 当脚本执行的语法错误

## 为什么不能把它直接算成 correctness bug

因为这个错误首先说明的是：

- 测试执行模式已经失真

如果 nested guest 自举过程没有持续留在 QEMU 下，得到的失败不再是对 NZCV 语义的干净观测。

## 当前知识库中的政策

- 对 `500.perlbench_r test` 单独失败保持谨慎
- 优先用已有 wrapper workaround 复核
- 不把它作为当前优化线的主 correctness gate

## 这页的作用

它不是在“替失败找借口”，而是在明确指出：

- 哪类 benchmark 结果是架构语义信号
- 哪类 benchmark 结果先被执行环境污染了
