# 关键回归与修复节点

## 节点 1：add-side lazy `B.cond` closure blocker

- first bad commit 被缩到 `6653c87c86`
- broader smoke / perf 二进制出现崩溃
- 说明 add-side lazy branch 条件映射并没有想象中那么安全

修复：

- `80acb12aae` 收窄 unsafe 条件子集
- 后续再以专门 lowering 恢复 add-like unsigned branch 子集

意义：

- 证明 branch 线也需要 correctness-first 收窄，而不是一路放宽

## 节点 2：compare-like `CSEL/CS*` correctness hole

- compare-like `CSEL/CS*` 曾被暂时 fallback
- `531.deepsjeng_r test` 暴露出旧生命周期模型不稳

修复：

- `47d27a1bb1` 用“消费条件后退休到 split flags”的模型恢复路径

意义：

- 这是当前项目最典型的一次“性能想象让位于生命周期正确性”的设计切换

## 节点 3：logic `CSEL/CS*` 相邻 host-flags 路径的本地 dirty-tree 回归

问题：

- 某些 `movi 0` 在 x86 上被 lower 成 `xor reg, reg`
- 直接把 live host flags 清掉

意义：

- 证明即使 guest 语义设计没问题，host codegen 细节也能把 direct-path 破坏掉

结果：

- 引入不破坏 flags 的常量物化方式
- 增强了对 logic line 的理解
