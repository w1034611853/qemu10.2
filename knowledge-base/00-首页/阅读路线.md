# 阅读路线

## 场景 1：我想继续往前开发

推荐顺序：

1. [[当前状态总览]]
2. [[当前风险、边界与未决问题]]
3. [[NZCV direct paths 与 producer chaining 当前状态]]
4. [[功能正确性总览]]
5. [[性能结果总览]]
6. [[NZCV 优化主时间线]]

这个顺序适合先知道“现在站在哪”，再决定下一条工作线值不值得做。

## 场景 2：我想做代码审视或设计评审

推荐顺序：

1. [[项目背景与目标]]
2. [[AArch64 NZCV 与宿主 x86 flags 的关系]]
3. [[pending_cc 与 producer-consumer 生命周期]]
4. [[Compare-like CSEL-CS 重构]]
5. [[为什么 compare-like CSEL 不能继续 peek+keep alive]]
6. [[TCG focused checks 总览]]

这个顺序适合先理解模型，再看最关键的一次设计切换。

## 场景 3：我想决定后续路线

推荐顺序：

1. [[当前风险、边界与未决问题]]
2. [[Lazy Compare Phase 2 - B.cond]]
3. [[Profile 分析与性能分化解释]]
4. [[为什么 lazy compare 先选 bounded gap-safe]]
5. [[关键回归与修复节点]]

这个顺序重点回答“什么值得做，什么不能贸然做”。

## 场景 4：我刚接手，需要 15 分钟内建立全局印象

推荐顺序：

1. [[项目背景与目标]]
2. [[当前状态总览]]
3. [[当前已完成能力矩阵]]
4. [[功能正确性总览]]
5. [[性能结果总览]]
6. [[NZCV 优化主时间线]]

1. 先打开对应知识笔记
2. 查看其 `source_docs`、`external_sources`、`related_commits`
3. 再看 [[来源总索引]]、[[知识笔记到原始文档映射]]、[[知识笔记到关键提交映射]]
