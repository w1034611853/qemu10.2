# 维护规范

## 核心分工

### `progress.md`

它是面向 AI / agent 的运行态 handoff 文档，优先记录：

- 当前分支、worktree、HEAD、最新提交
- 最近做了什么代码改动
- 当前 focused checks 和验证命令
- 下一步可直接继续推进的工作
- 已知坑点、回退点、调试上下文

### `knowledge-base/`

它是面向人的知识库，优先记录：

- 为什么这样设计
- 哪些方案被选中或放弃
- 当前能力边界和风险
- 应如何审视代码结构和生命周期模型
- 后续路线该怎么选

## 内容升级规则

先写进 `progress.md` 的内容：

- 临时调试发现
- 新提交的即时说明
- 某条 checker 刚跑通或刚失败
- 当前 worktree 操作信息

应该提升进知识库的内容：

- 已经稳定的阶段结论
- 会影响后续路线选择的判断
- 某个 correctness hole 的本质原因
- 某个性能结论的适用边界
- 某个机制模型的稳定理解

## `as_of` 规则

每篇核心笔记都必须带 `as_of`，表示：

- 这篇笔记的结论截至哪一天
- 不是“文件最后保存时间”
- 也不是“某个原始来源的日期”

更新逻辑：

- 如果只修正文案，不改变结论，更新 `updated`
- 如果结论边界发生变化，同时更新 `as_of` 和 `updated`
- 如果某篇笔记已被新结论替代，把 `status` 改为 `superseded`

## 来源规则

每篇核心笔记都应该尽量写清楚：

- `source_docs`
- `external_sources`
- `related_commits`

原则是让读者能从“知识结论”追到“原始依据”。

## 更新频率建议

- 高频：`progress.md`
- 中频：项目总览、优化专题、验证与证据
- 低频：机制与架构、决策与方案演进

## 不要做的事

- 不要把原始 spec 全文贴进知识笔记
- 不要让知识库变成按日期堆文件的档案馆
- 不要用知识库代替 `progress.md`
- 不要不写 `as_of` 就给出“当前状态”结论
